## Known limitations

- **Small samples.** Every case ran 1–3 times. The prompt dedup in this release showed no
  measurable cost change ("not confirmed — within noise", COST-BASELINE).
- **Not every case ran on the release code.** `run-plan-not-auto` and `deps-available` last ran on
  `5444a28`; since then only `sdd-engineering` prompt text changed.
- **No behavior evals** for `engineering-paved-path` or `research-tools`. Only `validate --strict`
  and loading checks cover them.
- **Version coverage.** Minimum Claude Code ≥ 2.1.110 is declared, not tested. Only 2.1.301 on
  Linux was tested.
- **Install path not exercised end to end.** Plugins were loaded with `--plugin-dir` and by
  `claude plugin eval`, not installed from the hosted marketplace with `claude plugin install`.
- **Dependencies in evals.** A plugin with `dependencies` loads disabled when evaluated from its own
  directory. Run evals from the repo root with `--eval-dir`.
- **`run-plan-not-auto` is a weak check.** `disable-model-invocation` makes `run-plan` invisible to
  the model, so the case confirms only that flag.
- **No security gate.** `sdd-engineering`'s `run-plan` has no security review step: DevDigest's
  `security-reviewer` was not extracted.
- **`next-best-practices` not shipped.** Its upstream has no license.
- **Updates are opt-in.** Auto-update is off by default for this third-party marketplace.
